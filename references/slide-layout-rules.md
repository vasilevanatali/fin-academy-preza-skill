# Правила вёрстки слайдов — чеклист качества

Свод правил, выведенных из правок Натали. Применять к КАЖДОМУ слайду деком школы.
Проверять в рендере (превью/PDF), а не на глаз в коде. Слайд = 1280×720.

## 1. Использование площади слайда

- Слайд обязан использовать всю полезную высоту. Запрещено: текст вверху + пустая нижняя
  половина (или наоборот). Это главный косяк, который Натали ловит первым.
- База против пустоты: контент по вертикали по центру —
  `.slide:not(.slide--cover):not(.slide--center) { justify-content: center; }` (.slide = flex column).
- Если после центрирования всё равно много воздуха — НАПОЛНИТЬ, а не оставлять:
  крупнее карточки/кегль, добавить 3D-объект/скрин/картинку, добавить плашку-вывод
  (lime `.card` с `border-color: rgba(168,232,74,.4); background: rgba(168,232,74,.08)`),
  разнести в две колонки `.two`.
- Эмпирика: свободного места снизу > ~150px → переверстать слайд.

## 2. Не выходить за край и не обрезать

- Контент НЕ вылезает за 720px (overflow) и НЕ обрезается снизу (плашки, картинки, нижние блоки).
- Проверка: у каждого `.slide` должно быть `scrollHeight <= clientHeight`.
- Длинные слайды ужимать классом `.compact` (см. ниже) или уменьшать картинки:
  `max-height` + `object-fit: contain`. Два скриншота в столбик почти всегда распирают слайд —
  ограничивать высоту (~200-220px каждому).

### Класс .compact (вставлять в `<style>` деком, вешать на тесные слайды)

```css
.slide.compact .title {
  font-size: 42px !important;
}
.slide.compact .two {
  margin-top: 14px !important;
}
.slide.compact .steps {
  gap: 14px !important;
}
.slide.compact .steps .h {
  font-size: 21px !important;
}
.slide.compact .steps .s {
  font-size: 17px !important;
  line-height: 1.3 !important;
}
.slide.compact .arr {
  font-size: 18px !important;
}
.slide.compact .photo {
  max-height: 360px !important;
  object-fit: cover !important;
}
.slide.compact .obj3d {
  max-height: 300px !important;
  width: auto !important;
}
```

## 3. Заголовки и переносы

- Без висячих предлогов/коротких слов на отдельной строке («для», «и», «а», «с»).
  Связку держать вместе: `Вайб-кодинг<br>для начинающих` (НЕ `для` отдельной строкой).
  Если длинная строка не влезает в колонку и слово сваливается — уменьшить кегль заголовка,
  а не плодить строки.
- Длинный заголовок + пояснение: заголовок крупный жирный (`.title`), пояснение ОТДЕЛЬНОЙ
  строкой меньшим кеглем (`.lead`/`.subtitle`), а не вся фраза одним размером в один `<h2>`.

### ЖЁСТКОЕ ПРАВИЛО ПРО ЧИСЛО СТРОК ЗАГОЛОВКА (частый косяк, ловит Натали первым)

Заголовок НЕ должен разъезжаться на лишние строки. Дефолтный `.title` = 54px, а левая колонка
`two--l` всего ~559px — длинные слова («ФИНАНСИСТУ», «ФИНАНСИСТ») при 54px не влезают и ломают
заголовок на 4 строки вместо задуманных 2. Это надо предотвращать СРАЗУ, а не чинить потом.

- **В теме деком всегда добавлять:** `.two--l .title { font-size: 40px; }` — заголовки в узкой
  левой колонке по умолчанию 40px, тогда 2 слова в строку влезают. Инлайн-размер перебивает
  правило, так что cover и спец-слайды не страдают.
- **Сколько строк задумано — столько и должно быть.** Число `<br>` в заголовке + 1 = задуманное
  число строк. Если в рендере строк БОЛЬШЕ — заголовок разъехался, уменьшить кегль до влезания.
- **Заголовок-предложение на весь слайд: максимум 2 строки.** 3+ строки = уменьшить кегль
  (но не мельче ~28px; если и тогда не лезет — сократить текст).
- **Кегли-ориентиры:** короткий заголовок в колонке 40px; заголовок-предложение во всю ширину
  32–44px; чем длиннее, тем меньше. Денежные/длинные в колонке — 28–32px.
- **Авто-проверка в превью (обязательна для каждого слайда с заголовком):**
  ```js
  document.querySelectorAll("h1.title,h2.title").forEach((h) => {
    const lines = Math.round(
      h.getBoundingClientRect().height /
        parseFloat(getComputedStyle(h).lineHeight),
    );
    const intended = (h.innerHTML.match(/<br/g) || []).length + 1;
    if (lines > intended)
      console.log("РАЗЪЕХАЛСЯ:", h.textContent.trim(), lines, ">", intended);
  });
  ```
  Любой `РАЗЪЕХАЛСЯ` в выводе — уменьшить кегль этого заголовка до совпадения строк.

## 4. Текст не склеивать

- Между блоками и пунктами достаточный отступ: `.steps { gap: 18-22px }`, line-height 1.3-1.45.
- Заголовок пункта и его описание разделять отступом (`.s { margin-top }`).
- Плотно прижатые строки («склеено») — увеличить gap/line-height, не уменьшать.

## 5. Выравнивание элементов

- Однотипные элементы — по одной линии. Суммы в карточках тарифов на ОДНОМ уровне
  (если в одной карточке есть badge, а в других нет — badge не должен опускать сумму).
- Badge «рекомендуем · популярный» выносить `position: absolute` НАД карточкой
  (родителю `position: relative; overflow: visible`), чтобы он не толкал контент вниз.
- Галочки/иконки/стрелки в списках выравнивать по первой строке текста через
  `display: grid; grid-template-columns: <иконка>px 1fr; align-items: start`
  (НЕ flex с `align-items: flex-start` — там иконка съезжает).

## 6. Картинки и белые блоки

- Белые карточки (QR, скрины) — компактные, по размеру содержимого, `width: max-content`,
  не растягивать на колонку (НЕ класс `.shot` с `min-height: 340px`).
- QR ~150px. Скрины в `.card-white` с `max-height` + `object-fit: contain`, чтобы видно целиком.

## 7. Стиль текста (правила Натали — дублируют общий стиль школы)

- Без длинных тире «—». Без конструкций «не X, а Y» / «не X, не Y». Без AI-штампов
  («важно отметить», «в современном мире», «без воды», «не просто X, а Y»).
- Цифры, тарифы, кейсы — проверять вебом перед вставкой (правило no-disinformation).
- Деньги с неразрывным пробелом: `49 000 ₽`, `≈15 млн ₽` (nbsp ` `). В index.html nbsp
  реальный символ — Edit матчит только с ним, при правках через python использовать `\xa0`.

## 8. Обязательная проверка перед сдачей

1. Превью: `python3 -m http.server` на папке деком (или launch.json).
2. eval-аудит в браузере по всем `.slide`:
   - overflow: `scrollHeight - clientHeight > 2` → вылезает;
   - underflow: позиция нижнего ребёнка, свободное место снизу > 150px → пусто.
3. Скрин каждого правленого слайда. Для одного слайда — спрятать остальные:
   `slides.forEach((s,i)=>s.style.display = i===N ? '' : 'none')` (full-page screenshot = ровно слайд).

### QR-коды

- Делать СТАТИЧЕСКИЕ QR (кодируют сам URL напрямую), не через сторонние сокращатели/редиректы —
  иначе протухнут. Генерация: `python3` + `qrcode[pil]`, `ERROR_CORRECT_H`, `fill_color="#0a0c09"`,
  `back_color="white"`, в `.card-white`. URL с `https://`, домены проверять `curl -I`.

4. Финальный PDF: Chrome headless `--headless=new --no-pdf-header-footer
--virtual-time-budget=45000 --print-to-pdf`. Проверить: число страниц == число слайдов,
   размер страницы 960×540pt (= 1280×720px). В `theme.css` нужен `@page {size:1280px 720px; margin:0}`
   - `@media print`.

### Вес PDF — держать лёгким (иначе Acrobat мерцает при прокрутке)

Тяжёлый PDF (>10 МБ) в Acrobat/просмотрщиках мерцает при пролистывании: страница не
успевает дорисоваться, мелькает чёрная половина. Держать дек в пределах ~6-10 МБ.

- **Облегчать через сжатие ИСХОДНЫХ изображений, не сам PDF.** Большие фото и скрины — это
  основной вес. `sips -Z 1200 фото.png` (resize), скриншоты и фото переводить в JPEG
  (`sips -s format jpeg -s formatOptions 85 x.png --out x.jpg`, заменить src в html).
  3D-объекты PNG — `sips -Z 650` (отображаются мелко). Типичные виновники: фото спикера
  (бывает 2-3 МБ), скрины демо, объекты по 0.5-0.7 МБ × много слайдов.
- **QR-коды НЕ переводить в JPEG** — только PNG, иначе замылятся и не сканируются.
- **НЕ сжимать готовый PDF через ghostscript `-dPDFSETTINGS=/ebook`** на деках со свечениями:
  gs делает flatten прозрачности и огрубляет мягкий radial-gradient-свет в резкие сплошные
  круги, которые ещё и перекрывают текст. Лёгкие изображения + пересборка Chrome'ом дают
  чистый результат без артефактов.

### ГЛАВНАЯ причина мерцания в Acrobat — ПРОЗРАЧНОСТЬ, а не вес

Если после облегчения PDF всё равно мерцает при прокрутке (мелькает чёрная половина
страницы) — дело в полупрозрачных слоях (alpha). Acrobat делает flatten transparency
на каждой перерисовке → мелькание. Чем больше rgba-слоёв на слайде, тем сильнее.

Источники, которые надо сделать СПЛОШНЫМИ (без alpha):

- фон слайда: `radial-gradient` со `rgba(...)`/`transparent` (свечение в углах) → заменить
  на НЕПРОЗРАЧНЫЙ `radial-gradient` со сплошными стопами (без `transparent`/`rgba`), напр.
  `radial-gradient(760px 580px at 87% 6%, #18260f, #0a0c09 56%)`. Так свечение в углу
  сохраняется (без него дек выглядит «чрезмерно чёрным»), но прозрачности нет — Acrobat не
  мерцает. Сплошной `var(--bg)` без свечения тоже не мерцает, но смотрится плоско, не надо;
  - Свечение СРАЗУ в нескольких углах одним CSS-градиентом не сделать без прозрачности
    (несколько непрозрачных radial перекрывают друг друга). Для 2-3 углов запекаю фон в одну
    непрозрачную картинку `bg-slide.jpg` (numpy: тёмный фон + radial-свечения в углах),
    ставлю `background: #0a0c09 url("bg-slide.jpg") center/cover`. ВАЖНО: при сохранении в JPEG
    плавный градиент даёт бандинг (концентрические кольца), особенно заметный в превью Google
    Drive. Лечится ДИЗЕРИНГОМ: добавить лёгкий шум `np.random.normal(0, 3.2, (H,W,1))` к
    картинке перед сохранением, `quality=93, subsampling=0`. Шум незаметен глазу, но убирает кольца;
- полупрозрачные карточки `--card-dark: rgba(...)` → сплошной цвет;
- границы `--hair: rgba(255,255,255,.1)` → сплошной;
- лаймовые плашки-выводы `background: rgba(168,232,74,.08)` + `border rgba(...,.4)` → сплошные.

Непрозрачный цвет подбирать как визуальный микс rgba на тёмном фоне `#0a0c09`, тогда вид
почти не меняется. Пример: `rgba(168,232,74,.08)` на фоне → `#171d0e`; `rgba(...,.4)`
border → `#45611f`; `card-dark .72` → `#161814`; `hair .1` → `#232521`.
Проверка: `grep -oE "(background|border-color)[^;]*rgba" index.html` должен дать 0.
PNG-объекты с альфа-каналом оставлять как есть — их растровую прозрачность Acrobat тянет нормально.
